# Cake Genius 🎂

متجر كيك ثنائي اللغة (عربي/إنجليزي، RTL/LTR) مع تخصيص كيك، تسعير ديناميكي بقواعد صريحة،
مساعد ذكي، سلة ودفع تجريبي، وقاعدة بيانات SQLite ولوحة إدارة محمية.

A bilingual (AR/EN, RTL/LTR) cake store with cake customisation, rule-based dynamic pricing,
a smart assistant, cart + demo checkout, SQLite persistence and a protected admin dashboard.

---
## 0. ما الجديد في 1.2

- **طبقة تخزين مجرّدة**: نفس الكود على SQLite أو PostgreSQL. SQLite يبقى الافتراضي بلا تبعيات، و`pg` تبعية اختيارية تُحمَّل فقط عند ضبط `DATABASE_URL`.
- **أداة ترحيل** `tools/migrate-sqlite-to-pg.mjs`: تنشئ المخطط، تنسخ الجداول بترتيب المفاتيح الأجنبية، تقارن العدّ والإجماليات، وتُكمل رموز الطلبات من أعلى رمز مرحّل.
- **سعة إنتاج وفترات تسليم**: سعة يومية وسعة لكل فترة، تُحجز داخل معاملة الطلب بـ `UPDATE ... WHERE booked + ? <= capacity`، فلا يمكن بيع آخر قطعة مرتين. إلغاء الطلب يعيد السعة.
- **لوحة تشغيل**: لوحة اليوم (سعة + طلبات بالفترة)، إنشاء منتج وتعطيله، إعدادات السعة، تصدير CSV بترميز UTF-8 مع BOM.
- **مشاركة وSEO**: Open Graph، Twitter، JSON-LD (Bakery + قائمة)، sitemap، robots، وصورة مشاركة 1200×630 مولّدة محلياً (`npm run og`).
- **إشعارات واتساب جاهزة وغير مفعّلة**: النص يُولَّد ويُخزَّن في `notification_outbox` بحالة `queued`، والمعاينة تعرض رابط `wa.me` يدوي. لا توجد دالة إرسال في الكود.
- **وضع `READ_ONLY=1`**: الخادم يرفض الكتابة ويجيب `503 PERSISTENCE_FAILED`، فلا يظهر طلب لم يُحفظ.

التفاصيل: `docs/PLAN-1.2.md` و`docs/POSTGRES-EVALUATION.md` و`docs/DELIVERY-1.2.md`.

## 1. البنية التقنية ولماذا

| القرار | السبب |
| --- | --- |
| **Node.js 22 + `node:http`** بلا أي حزمة إنتاجية | التطبيق كله يعمل بـ `node server.js`. لا `npm install` على الاستضافة، لا تبعيات تتعطل، وبدء الخدمة فوري (مهم على مثيلات Render المجانية التي تنام). |
| **`node:sqlite`** (مدمج في Node 22) | قاعدة بيانات حقيقية، ملف واحد، معاملات ACID وWAL. لا خادم DB منفصل، لا تكلفة، والبيانات تبقى على القرص بين إعادات التشغيل. |
| **طبقة مستودع غير متزامنة** (`lib/db.js` + `lib/storage/`) | كل SQL مكتوب مرة واحدة، والمشغّل يختار SQLite أو Postgres حسب `DATABASE_URL` ويترجم `?` إلى `$n`. الحجز والسعة والتراجع كلها داخل معاملة المشغّل. |
| **واجهة Vanilla JS + CSS** بلا إطار عمل | صفحتان فقط؛ لا حاجة لـ build step ولا SSR. أسرع تحميل وأقل نقاط فشل، والدعم RTL/LTR يتم بخاص الملف `dir` وخصائص CSS المنطقية (`margin-inline` …). |
| **SVG محلية للصور** (`tools/gen-images.mjs`) | لا اعتماد على شبكة خارجية للصور، الصور تعمل دون إنترنت، وCSP يمكن أن يبقى صارماً. |
| **جلسات بكوكيز HttpOnly + scrypt** | لا JWT في `localStorage`، لا كلمات مرور في الكود أو الواجهة، وتخزين فقط لـ hash + salt في SQLite. |

قاعدة واحدة تحكم كل الأسعار: `lib/pricing.js`. الواجهة لا تحسب مالاً أبداً؛ تسأل `POST /api/quote`،
والخادم يعيد حساب كل سطر في السلة عند الدفع، فلا يمكن التلاعب بالسعر من المتصفح.

## 2. التسعير (القواعد الفعلية)

سعر القاعدة = سعر كيكة 6 إنش بالخيارات الافتراضية. ثم:

| العنصر | القاعدة |
| --- | --- |
| الحجم | معامل على سعر القاعدة: 6" ×1.00 · 8" ×1.35 · 10" ×1.85 · طابقان ×2.40 |
| النكهة | إضافة ثابتة: فانيلا 0 · شوكولاتة +15 · ريد فيلفيت +25 · فستق +35 · مانجو +20 |
| الحشوة | كريمة 0 · مربى فواكه +15 · غاناش +20 · لوتس +25 |
| التصميم | كلاسيكي 0 · مينيمال +20 · زهور +45 · ثيم +60 · طبعة صورة +70 |
| الرسالة | أول 30 حرفاً مجاناً، ثم +12 لكل 20 حرفاً إضافياً (الحد 120) |
| تنفيذ مستعجل | +25% على مجموع الكيكة إذا كان التسليم أقل من 24 ساعة |
| التسليم | استلام 0 · توصيل داخل المدينة +25 **لكل سطر طلب** (لا يُضاعف مع الكمية) |

الإجمالي = (سعر الحجم + النكهة + الحشوة + التصميم + الرسالة) + المستعجل + التسليم، كله بالريال الصحيح.

### الكمية (BUG-001)

- الكمية لكل سطر بين 1 و20، **سعر الوحدة لا يتغير بالكمية**.
- `إجمالي السطر = سعر الوحدة × الكمية + رسوم التوصيل`، ورسوم التوصيل تُحسب مرة واحدة لكل سطر.
- الواجهة تعرض الثلاثة منفصلة (سعر الوحدة / الكمية × السعر / إجمالي السطر)، لأن عرض سعر الوحدة
  تحت عنوان «الإجمالي» كان سبب البلاغ الأصلي.
- الحساب مشترك بين المتصفح والخادم في ملف واحد: `public/lib/cart-math.js` (يستورده `server.js` أيضاً).
- الخادم يتحقق أن الكمية عدد صحيح 1–20، ويعيد حساب سعر الوحدة من محرك التسعير، ويتجاهل أي
  `unitPrice`/`lineTotal`/`total` يرسله المتصفح.
- اختبارات: `tests/cart-math.test.mjs` (حساب الوحدة/الكمية/السلة) + 26 فحصاً في
  `tests/acceptance.mjs` تغطي الكميات 1 و2 و3، والقراءة من قاعدة البيانات، ومحاولة التلاعب.

الواجهة تعرض كل بند من الفاتورة (`breakdown`) القادم من الخادم، ولا تعرض رقماً من عندها.

## 3. المساعد الذكي — AI Cake Designer

هذا الإصدار يحوي **مصمم كيك حقيقي بالذكاء الاصطناعي** (`lib/ai-assistant.js`) يعمل بنموذج
`deepseek-v4-pro` (DeepSeek API). النموذج **لا يحسب أي سعر ولا يخترع أي منتج أو خيار أو مخزون أو
موعد تسليم**: وظيفته فهم اللغة الطبيعية (عربي/إنجليزي) وكتابة نص توضيحي فقط.

1. `POST /api/assistant/ai` يرسل الكتالوج الفعلي (المنتجات والخيارات) إلى النموذج، فيستخرج
   بنية منظمة: المناسبة، عدد الأشخاص، الميزانية، النكهة، التصميم، طريقة التسليم، الاستعجال، والموعد.
2. الخادم يتحقق من كل معرّف ضد الكتالوج الحقيقي ويرفض أي مجهول، ثم يعيد حساب كل سعر من
   `quote()` نفسها — المحرك الوحيد المستخدم في الكاشير. النموذج لا يرى نتيجة السعر إطلاقاً.
3. الطلب الغامض يعيد أسئلة توضيحية (محادثة متعددة الأدوار عبر `history`). الطلب المتعذّر
   (ميزانية أقل من أي منتج، أو طلب نباتي/بدون سكر غير متوفر) يفسّر البدائل الحقيقية الأقرب ولا يخترع بديلاً.
4. الطلبات الكبيرة (أكثر من 30 شخصاً) تُغطى بضرب الكمية تلقائياً، وكل اقتراح يحمل إعداد سلة
   صالحاً يُضاف للسلة بضغطة واحدة.

القيد الصارم: المفتاح يُقرأ من `DEEPSEEK_API_KEY` وقت التشغيل فقط، ولا يظهر في أي استجابة ولا
يُلتزم في المستودع. بدون المفتاح، أو عند فشل الاتصال بالنموذج، يتراجع الخادم تلقائياً إلى المساعد
القواعدي القديم ويعلن ذلك (`fallback: true`).

النتيجة: النموذج يفهم اللغة، والخادم يحسب المال، ولا يمكن التلاعب بالسعر من المتصفح أو من النموذج.

## 4. التشغيل محلياً

```bash

ADMIN_PASSWORD=your-pass node server.js
PORT=8080 DB_PATH=./data/cake.db node server.js
```

المتغيرات:

| المتغير | الافتراضي | الاستخدام |
| --- | --- | --- |
| `PORT` | `3000` | منفذ HTTP |
| `DB_PATH` | `./data/cake.db` | مسار ملف SQLite |
| `ADMIN_USER` | `admin` | مستخدم اللوحة |
| `ADMIN_PASSWORD` | `cake-admin-2026` | كلمة مرور اللوحة (تُزامن مع الـ hash عند الإقلاع). الافتراضي **للتطوير المحلي فقط** — أي نشر حقيقي يجب أن يضبط سراً خاصاً به عبر متغير البيئة، والخادم يطبع تحذيراً إذا شُغّل في الإنتاج بالافتراضي. |
| `DEEPSEEK_API_KEY` | *(لا يوجد)* | مفتاح DeepSeek للذكاء الاصطناعي. يُقرأ وقت التشغيل فقط ولا يُلتزم. بدونه يتراجع المساعد إلى الوضع القواعدي. |
| `DEEPSEEK_MODEL` | `deepseek-v4-pro` | النموذج المستخدم (اختياري). |
| `DATABASE_URL` | *(لا يوجد)* | رابط PostgreSQL. عند ضبطه يُستخدم Postgres بدل SQLite، ويجب أن تكون حزمة `pg` مثبتة (تبعية اختيارية). |
| `READ_ONLY` | `0` | `1` يفتح قاعدة موجودة للقراءة فقط؛ كل كتابة تُرفض و`POST /api/orders` يعيد `503 PERSISTENCE_FAILED`. |
| `PUBLIC_URL` | *(من ترويسة الطلب)* | الأصل المطلق المستخدم في canonical وOG وsitemap. |
| `WHATSAPP_ENABLED` + `WHATSAPP_TOKEN` + `WHATSAPP_PHONE_NUMBER_ID` | غير مفعّلة | تُجهّز قناة الإشعارات. لا يوجد مُرسل في الكود؛ النصوص تُخزَّن في `notification_outbox` فقط. |

لا توليد مفاتيح ولا حزم. المتطلبات: Node ≥ 22.5 (من أجل `node:sqlite`).

## 7. الأمان

- كل مسارات `/api/admin/*` تتحقق من الجلسة على الخادم؛ لا يوجد إخفاء واجهة كبديل عن التحقق.
- كلمات المرور: `scrypt` بـ salt عشوائي، مقارنة `timingSafeEqual`.
- حد 6 محاولات دخول لكل IP في 10 دقائق، وجلسة 8 ساعات.
- المساعد بالذكاء الاصطناعي محمي بحد طلبات لكل IP (20/دقيقة) وسقف تزامن (4) وحد توكن لكل طلب (8000)؛ المخالفة تعيد `429` مع `Retry-After`.
- عنوان العميل يُستخرج من `X-Forwarded-For` فقط عبر بروكسي موثوق (قائمة `TRUSTED_PROXIES` بالـ IP/CIDR، تُقارن بعنوان النظير المباشر) — **ليس** بـ `NODE_ENV=production` وحده. حدود الاستهلاك **محلية لكل عملية Node** ولا تشكل سقفاً مالياً شاملاً عبر عدة مثيلات؛ للسقف الشامل تحتاج بوابة موحّدة خارجية.
- صلاحية المدخلات على الخادم: الاسم (2-60 بلا وسوم)، الجوال (9-15 رقماً)، البريد، الكمية (1-20)،
  الموعد (ساعة إلى 60 يوماً)، الحالة من قائمة محددة، السعر (20-5000).
- حدود حجم الجسم (128KB)، ترويسات CSP و`X-Frame-Options: DENY` و`nosniff`، وحماية من path traversal.
- لا بطاقات ولا دفع حقيقي ولا إرسال رسائل للعملاء، وكل بيانات العملاء في الاختبارات وهمية.

## 9. حدود معروفة

- الدفع تجريبي بالكامل: `payment_method = demo`، لا بوابة دفع ولا تحصيل.
- المساعد يعمل بنموذج خارجي عند وجود المفتاح، ويرجع إلى محرك قواعدي محلي بدونه؛ لا يحسب سعراً ولا يخترع منتجاً في الحالتين.
- **الإنتاج المنشور ما زال على 1.1** (`100ca3e`) وعلى SQLite داخل الحاوية: 1.2 يضيف مسار Postgres كاملاً ومختبَراً، لكن لم تُنشأ قاعدة خارجية ولم تُغيَّر خدمة Render (يحتاج موافقة المالك).
- **الإشعارات لا تُرسل**: النصوص تُولَّد وتُخزَّن بحالة `queued` فقط. التفعيل يحتاج حساب WhatsApp Business، قالباً معتمداً، وتكلفة محادثات.
- **الصور**: الكتالوج ما زال على رسومات SVG مولّدة. المشرف يستطيع إدخال مسار صورة أو رابط https، لكن الصور الفعلية تحتاج صوراً أصلية من المالك أو مرخّصة.
- **الدفع والفاتورة**: لا بوابة دفع ولا فاتورة إلكترونية (ZATCA)؛ أي بيع حقيقي يحتاج قراراً منفصلاً.

## 10. استمرارية البيانات (قيد موثّق)

| البيئة | النتيجة | الدليل |
| --- | --- | --- |
| محلي (Windows + SQLite) | **PASS** | أوقفت عملية الخادم قسراً (`Stop-Process -Force`) ثم أعدت تشغيلها: بقي الطلب `CG-1001` بحالته `baking` و`/api/health` أعاد `ordersStored: 1`. |
| Render (خطة free) | **FAIL — قيد منصة معروف** | أعدت تشغيل الخدمة عبر `POST /v1/services/{id}/restart`: نزل `ordersStored` من 1 إلى 0. Render: *"Free web services cannot attach disks."* |

**بيانات الطلبات على Render مؤقتة بطبيعتها:** تُخزَّن في ملف SQLite داخل حاوية المثيل، وتُفقد عند أي
إعادة تشغيل، أو إعادة نشر (أي دفعة جديدة إلى `main`)، أو إعادة إيقاظ بعد خمول (الخدمة المجانية تنام
بعد 15 دقيقة بلا زيارات). لا يوجد تخزين دائم ولا نسخة احتياطية ولا نقل بيانات في هذا الإصدار.
